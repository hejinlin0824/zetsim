# zetsim 学习路线与专业工作流

这份路线把 zetsim 从“能运行固件的仿真器”组织成一套可循序完成的嵌入式实验平台。当前 Web 案例库提供 6 个可观察、可复验的实验；案例中的寄存器示意与可编译 C 工程会明确区分。

## 推荐学习顺序

| 编号 | 案例 | 关键知识 | 浏览器中看什么 | 完成标准 |
|---|---|---|---|---|
| 01 | GPIO 输出：点亮第一盏灯 | RCC 时钟门控、GPIO CRL、输出电平 | LED、PA5 探针、暂停/复位 | LED 按约 250 ms 节拍翻转；复位可重跑 |
| 02 | 8 路 LED 跑马灯 | 位运算、寄存器映射、SysTick 延时、C 工程 | 8 个 LED、编译日志、固件运行 | 修改 STEP_MS 后，跑马灯速度随之变化 |
| 03 | 外部中断：按一下只触发一次 | GPIO 输入、EXTI 边沿、NVIC、pending 清除 | 按键动作与 LED 变化 | 5 次完整按键对应 5 次翻转 |
| 04 | USART1 串口 | BRR、TXE、RXNE、中断回显 | 串口终端 | 输入内容被固件逐字符回显 |
| 05 | PWM + ADC | PSC/ARR/CCR、PWM、ADC 通道映射 | PA0 示波器、电位器 PA1 电压 | 约 10 kHz、30% PWM；电位器覆盖 0–3.3 V |
| 06 | RC 低通滤波 | 时间常数 τ=RC、平均值、纹波 | 电阻、电容、探针、示波器 | 1 kΩ + 100 nF 的节点波形被滤波，均值约 0.99 V |

## 每个案例应该包含什么

1. **目标**：明确学习者需要解释或完成的一个电路行为。
2. **接线表**：列出 MCU 引脚、器件端子、电源与观察点。
3. **原理/代码阅读点**：给出实际源码路径、寄存器解释，以及该代码是可编译源文件还是演示固件生成逻辑。
4. **动手任务**：不只是点击运行，还要改参数、对照波形或修改 C 工程。
5. **验收标准**：必须能在仿真时间、LED、终端或示波器上观测，不能只以“没报错”为通过。
6. **常见故障**：至少覆盖未使能时钟、引脚映射错误、未接公共地、探针接错节点、保存失败与缺少交叉编译器。

## C 项目工作流

- 打开工具栏的“项目”，选一个项目后阅读 `main.c`、`startup.c`、`stm32f103.h` 和 `link.ld`。
- 编辑后查看编辑器的未保存状态。使用 **Ctrl+S** 保存，使用 **Ctrl+Enter** 保存并编译运行。
- 保存失败时不应继续编译；编译成功后，检查日志中的产物路径和 LED/终端/示波器行为。
- 切换项目时，如果当前工程存在未保存修改，应先决定是否放弃；不要默默把一个项目的缓冲区写进另一个项目。
- 浏览器内编辑的 C 源文件存放在本地 `projects/<name>/` 目录。它们不是 GitHub 上的自动提交，也不应被当成版本控制。

## 布线检查的覆盖范围

Web 版“布线检查”目前覆盖以下基础规则：

- 导线端点是否引用存在的元件和有效引脚；
- 完全重复或自连的导线；
- MCU 的 VDD 是否直接接到 +3.3V 符号、VSS 是否直接接到 GND 符号；
- 常见元件端子、探针和电源/地符号是否有导线；
- LED 直接驱动且未见显式限流电阻时给出教学性警告。

这是帮助学习者发现常见接线问题的规则检查器，不是完整的 ERC/DRC 工具，也不替代 SPICE 求解。它暂不完整识别复杂网络上的串联关系、同网等价、模拟输入量程、驱动争用、电源功耗、PCB 间距或制造约束。报告中的警告不阻止仿真；在真实硬件上电之前仍需独立核查电路设计。

## 布线习惯

- 先规划电源、地、信号路径，再摆放元件；相关信号尽量沿网格走线。
- 避免不必要的线交叉；交叉时不要把视觉交叉误认为电气连接。使用明确引脚或同网端点完成连接。
- 把探针放在真正想观察的网络节点，而不是只放在相邻元件附近。
- 真实 LED 电路要配置限流电阻；MCU 输出和外设接口应检查电压范围、负载与共地要求。
- 每搭好一部分电路就运行“布线检查”，再用一个已知固件验证预期节点行为。

## 当前边界与后续建设

案例库中的 blink、button_exti、hello_echo、pwm_adc 属于 `tools/gen_firmware.py` 生成的演示固件。当前六个案例均有独立的可编辑 C 项目，采用共同的 `main.c`、`startup.c`、`stm32f103.h` 与 `link.ld` 工程骨架：

| 案例 | 工程目录 | 实战重点 |
|---|---|---|
| GPIO 闪灯 | `projects/gpio_blink` | RCC、GPIO 输出、SysTick 延时 |
| 8 灯跑马灯 | `projects/led_marquee` | 位运算、GPIO 多路输出、循环 |
| EXTI 按键 | `projects/exti_button` | EXTI/NVIC 配置与中断向量表 |
| USART1 回显 | `projects/uart_echo` | TXE/RXNE 状态位与轮询收发 |
| ADC 控制 PWM | `projects/pwm_adc_control` | ADC1 采样值映射到 TIM2_CCR1 |
| RC 滤波 | `projects/pwm_rc_filter` | 固定 PWM 信号源、RC 时间常数与纹波 |

案例库里的预编译 HEX 仍保留为“快速观察”路径；想改代码并做实战时，打开对应 C 工程、保存、编译和运行。跨平台编译器缺失时，先运行根目录的 `python setup_env.py`。项目源码已加入结构与关键寄存器路径测试，但新建的 C 工程仍需在本地工具链和浏览器里逐一编译、运行验收；静态测试本身不能替代真实编译或电气验证。

推荐的长期建设顺序：

1. 为每个案例配独立可编译 C 项目和对应原理图 JSON。
2. 为原理图增加命名网络、线路选择、网络高亮和真正的网表 ERC。
3. 增加代码运行/暂停断点、寄存器观察、GPIO 事件时间线、编译错误点击定位。
4. 建立课程进度保存、挑战任务、自动判题和案例回归套件。
